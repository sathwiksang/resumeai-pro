# ResumeAI Pro — Pre-Release Audit (2026-07-10)

Scope: full audit ahead of a hardened production release. Covers code
(tenant isolation, authorization, auth/session, billing, jobs, uploads),
production data hygiene, and infrastructure. Live feature-matrix results
are appended at the end.

Environment: Rails 8.1 + Inertia/React (Vite), `acts_as_tenant` (tenant =
signed-in user's organization), Pundit, Solid Queue in Puma, Active Storage
(disk), local Ollama LLM. One container behind Caddy on a single EC2 host.

Severity: **CRITICAL** (data exposure / takeover) · **HIGH** (security or
core feature broken) · **MEDIUM** (correctness / trust) · **LOW** (polish).

---

## CRITICAL

### C1 — Cross-tenant user exposure in the Team Members admin
`app/models/user.rb` has **no `acts_as_tenant`**, and:
- `app/policies/user_policy.rb:16` — `Scope#resolve` returns `scope.all` for any admin.
- `app/controllers/admin/users_controller.rb:78` — `set_user` does `User.find(params[:id])` (global).
- `UserPolicy#show?/update?/destroy?` only check `user.admin?`, never that the record belongs to the admin's org.

**Effect:** any org admin, on `/admin/users`, sees **every user in every
organization**, and can open/edit/**delete** any of them by ID. This is
the "lots of seed data" reported — the Team Members list currently shows
all 11 accounts from unrelated test orgs. This is both a data-confidentiality
breach and a cross-tenant integrity/destruction risk.

**Fix:** scope all user queries to `current_organization.users`; `UserPolicy`
must compare `record.organization_id == user.organization_id`; `Scope`
admin branch → `scope.where(organization_id: user.organization_id)`.

### C2 — `/admin/jobs` (Mission Control) mounted with no authentication
`config/routes.rb:64` — `mount MissionControl::Jobs::Engine, at: "/admin/jobs"`
with no `authenticate` constraint and no initializer configuring HTTP basic
auth. The job dashboard exposes every background job and its **arguments**
(user IDs, record IDs, potentially PII) and lets anyone retry/discard/kill
jobs.

**Fix:** wrap the mount in an authenticated + admin-only route constraint
(a `Constraint` object that resolves the session cookie and checks
`user.admin?`), or configure Mission Control's HTTP basic auth from ENV.

## HIGH

### H1 — Password change requires no current password
`app/controllers/admin/settings_controller.rb:39` — the "password" section
calls `current_user.update(password_params)` with only `password` +
`password_confirmation`. An attacker with a live session (shared/kiosk
machine, stolen cookie) can change the password and lock the owner out
without knowing the existing one.
**Fix:** require and verify `current_password` before updating.

### H2 — Any admin can self-upgrade to Enterprise for free
`app/controllers/admin/billings_controller.rb:` `create_checkout` — when
`current_organization.stripe_enabled?` is false (it is false in production;
no `STRIPE_SECRET_KEY` is set), it falls through to `upgrade_plan!(plan)`
with **no payment**. Any admin can move their org to Enterprise (unlimited
analyses). The `sathwiktest` org is already on Enterprise via this path.
**Fix:** for a portfolio/demo build, either (a) hard-disable plan changes
when Stripe is off and label the billing page "Demo — billing not enabled",
or (b) gate the dev-switch behind an explicit `DEMO_BILLING=1` flag. Do not
present a free unlimited upgrade as if it were a purchase.

### H3 — Invitation emails silently fail; failed jobs accumulate
No SMTP is configured in production, so `InvitationMailer#invite`
(`deliver_later`) dies with `Errno::ECONNREFUSED :25` every time; the
invitee never receives anything. Two such `SolidQueue::FailedExecution`
rows already exist and will grow with every invite/resend.
**Partial mitigation shipped:** the invitations UI now exposes a copyable
accept link. **Remaining fix:** configure a real mail transport (reuse the
Ekklesia Resend/SES credentials) OR make delivery best-effort so a mailer
failure never becomes a persisted failed job, and surface the copy-link as
the primary path until email is on.

## MEDIUM

### M1 — Content-Security-Policy is report-only
`config/initializers/content_security_policy.rb:26` —
`content_security_policy_report_only = true`. The (otherwise strict) CSP is
advisory; nothing is actually blocked. For a "secure as possible" release
it should enforce, with report-only kept only for a short bake if desired.
**Fix:** set report-only false in production (nonce-based script/style are
already wired).

### M2 — No reaper for stuck analyses
If a scoring/extraction job dies from an error type that isn't caught
(worker OOM/kill, unexpected exception), the `ResumeScore` stays `queued`/
`analyzing` forever — one such row already exists in production. Users see a
spinner that never resolves.
**Fix:** a periodic job (Solid Queue recurring) that marks scores
`analyzing`/`queued` older than N minutes with no active job as `error`
("timed out"), so the UI shows a retriable failure.

### M3 — Enterprise usage display shows "used / 0"
`Organization#upgrade_plan!` sets Enterprise `monthly_analysis_limit: 0`,
while `can_analyze?` special-cases Enterprise as unlimited. The dashboard
`usage.limit` reads the raw `monthly_analysis_limit` (0), so an Enterprise
org shows "N / 0" instead of "N / Unlimited".
**Fix:** serialize the effective limit (Unlimited/∞ → sentinel) consistently
from `plan_limits`, not the raw column.

### M4 — Open self-service registration with no email verification
`/registration/new` creates an organization and an **admin** with no email
confirmation. Combined with H2 this yields free unlimited accounts on
throwaway emails. Acceptable for a demo, but should be a conscious choice.
**Fix (min):** note it in SECURITY.md; optionally add email verification or
a simple signup throttle (rack-attack already covers 10 auth POST/min/IP).

## LOW

- **L1** — Login does not rotate the Rails session (`SessionsController#create`).
  Low impact (auth is a DB-backed `Session` + signed permanent cookie, not
  the Rails session), but rotating on privilege change is good hygiene.
- **L2** — Registration `subdomain` uniqueness is global and immutable-by-collision;
  no reserved-word list (e.g. `www`, `api`, `admin` could be registered as an org
  subdomain and shadow a workspace host). Add a reserved list.
- **L3** — Some Inertia serializers already guard nils; keep that consistent for
  any new fields (avoid `Invalid Date`/`NaN` in the UI).

## Production data hygiene (as of audit)

- **11 organizations**, 9 of which are throwaway test/probe orgs created
  during this session (`probe-*`, `verify-*`, `score-*`, `qs-*`, `il-*`) plus
  the owner's two (`testsathwik` free, `sathwiktest` enterprise-via-H2).
- 3 resumes / 3 JDs / 3 scores — all from automated probes (`resume-sample.txt`,
  "Senior Software Engineer"). **No SampleDataGenerator content exists in any
  live org** — `SampleDataGenerator` is only invoked from `db/seeds.rb`, never
  from a request path, so fresh production orgs start empty (good).
- **1 score stuck** in a non-terminal state (pre-dates the model fix); see M2.
- **2 failed mailer jobs**; see H3.

**Action:** purge all test/probe orgs (and dependent rows) from production,
keeping only what the owner wants. The user-visible "seed data" is C1, not
seeded rows — fixing C1 removes it.

## Infrastructure

- **I1 — Workspace wildcard DNS is proxied.** `*.resume.sathwiksangeethamproject.dev`
  resolves to Cloudflare's anycast IPs (proxied / orange-cloud), so Caddy's
  on-demand TLS handshake never completes (`curl` to a workspace host returns
  no TLS). The record must be **DNS-only (grey cloud)** pointing at the Elastic
  IP `100.52.7.135`, like the other app records. App + Caddy config are correct
  and verified (`/subdomains/check` returns 200 for real orgs, 404 otherwise).
